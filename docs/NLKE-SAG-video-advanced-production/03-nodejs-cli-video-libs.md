# Node.js / CLI Declarative Video Editing Libraries

## Editly (mifi/editly)
- **What**: "Slick, declarative command-line video editing & API" — a Node.js + FFmpeg framework for declarative non-linear editing (NLE) [web:29][web:34].
- **Capability**: Programmatically or via CLI, assemble a video from clips, images, audio, and titles, with smooth transitions and background music overlay — no GUI required [web:31][web:34].
- **Install**: `npm i editly` (or `-g` for CLI); requires ffmpeg (`brew install ffmpeg` pulls ffprobe too) [web:30][web:31].
- **Language**: TypeScript, ~5.2k stars, GitHub topic "video-editor" [web:43].
- **Ecosystem**: `editry` provides R language bindings; Docker image also available (`scienceuntangled/editly`) [web:33].
- **Usage style**: Pass a JSON/JS config object describing an ordered list of "clips" (each with layers of video/image/title/audio) → editly renders final MP4. Ideal for **fully automated, headless** short-form video assembly (e.g., stitching AI-generated Veo clips + captions + music) inside a server pipeline.
- **Relevance to NLKE-SAG**: Strong fit for the **server-side / batch rendering** stage of the pipeline — take Veo/omni-generated segments plus AI-written titles/captions and assemble final social posts without a GUI, driven entirely by JSON specs generated by an LLM agent.

## FFCreator (tnfe/FFCreator)
- **What**: A fast, Node.js-based video processing/production library (JavaScript), described as "a high-speed video creation library based on node.js," oriented toward short-video generation [web:43].
- **Relevance**: Alternative to Editly for programmatic short-video assembly; worth comparing rendering speed and feature parity (transitions, subtitles, scene composition) for a content-factory pipeline generating many short clips per day.

## LosslessCut (mifi/lossless-cut)
- See `02-ffmpeg-wasm-browser-editing.md` for full detail — included here as it is also usable as a **desktop companion tool** (Electron, TypeScript) for manual lossless trims/crops before AI post-processing, and exposes an **HTTP API** for scripted automation of cut/export actions [web:69][web:72].

## OpenTimelineIO (OTIO) interoperability
- Not covered by a dedicated TypeScript port in current search results, but relevant as an **interchange format**: Editly, Remotion timeline builds, and desktop NLEs (DaVinci Resolve, Premiere) can be bridged via FCPXML/OTIO export for round-tripping between an AI-automated rough-cut and manual fine-editing in a professional NLE. Auto-editor (see doc 05) already exports directly to DaVinci Resolve and Premiere FCPXML, which is the most practical current bridge for this pipeline rather than raw OTIO tooling.
